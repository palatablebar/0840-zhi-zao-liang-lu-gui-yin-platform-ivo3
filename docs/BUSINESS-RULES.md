# 业务规则

## 使用者

工厂工艺工程师使用本工作台处理首检良率与返工归因。

## 主规则

首检良率不把返工良品算作一次通过，滚动良率按各工序首检良率相乘。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

## 批次

同一来源重复执行得到同一批次数值。签发要求阻断项为零，并携带当前版本号；旧版本提交会被拒绝。证据只在签发后生成。

## 成品扣货

发现某道工序混进可疑来料后，发货前按下列规则圈定必须扣住的成品：

1. **可疑来料追溯**：报工以投入/产出批次建立血缘，可疑来料沿报工产出边能到达的成品一律扣住（`SUSPECT_LINEAGE`）。
2. **批次拆分与混装**：报工可补记一次投入多批次（混装）和一次拆出多批次（拆分），每笔去向和数量都参与追溯，扣货数量按产出数量累加。
3. **交接只对得上总量**：交接 `from_qty == to_qty` 但未登记逐批次去向时，可能混到的成品都得扣住（`MIX_UNVERIFIED`）；报工血缘能证实没混到的批次当天照发（`CLEAN_LINEAGE`）。
4. **交接数量对不上**：`from_qty != to_qty` 时，经过这笔交接的成品不能放行（`HANDOVER_MISMATCH`），不区分血缘。
5. **晚到记录恢复放行**：补齐交接逐批次去向或补记报工后，证实无涉的成品恢复放行（`HANDOVER_CONFIRMED_CLEAN`）；可疑下游仍扣住。
6. **重跑幂等**：同一 `investigation_id` 重跑只更新结论与版本号，不重复生成扣货记录；未给标识时按请求内容生成稳定键。
7. **工作台可查**：`GET /api/holds/results` 汇总所有排查下仍处扣货状态的成品批次。

后道工序消费、却没有任何报工产出的断链中间批，其下游成品无法证实未混入，扣住为 `LINEAGE_GAP`；交接应发生而无记录时为 `HANDOVER_MISSING`。
